**Goal:** The app people and judges use: the gates, a fresh photo from an in-app camera with its GPS fix, MMDA's level at that spot with its evidence or an honest "can't tell", a live map of pins, the Tested page with samples, and the privacy page, on the web as a PWA and on Android as an APK.

**Architecture:**
- **One React app** in `app/`, with hash routes, a shared layout that carries the screen line, string tables for English and Taglish, and one result card used by every screen that shows a reading.
- **Pure modules** hold every rule that can be tested without a screen: polling, retries, the quality scores, distances, wording, fading, the summary loader.
- **Thin wrappers** reach the outside world: the API client, the browser camera stream, Capacitor's geolocation, Leaflet, `localStorage`.
- **The backend** changes only for hosting, once Rene answers MS5-Q4: the host and the web origin in two CORS lists, in the one SAM template (C600, C622, Task 19). Until then the web app is a static build output that any host can serve.

**Tech Stack:**
- React 19.3, Vite 8.3, TypeScript 7.0 (strict), Tailwind CSS 4.3, Capacitor 8.5 with `@capacitor/geolocation` 8.2. `@capacitor/camera` is removed (C602).
- new, with the versions and licences npm listed on Oct 28 (pin whatever is current at install, after Context7): Leaflet 1.9.4 (BSD-2-Clause) and `@types/leaflet`, `vite-plugin-pwa` 2.0.0 (MIT), `marked` 18.1.2 (MIT), `lucide-react` 1.63.0 (ISC), and `@fontsource/atkinson-hyperlegible-next` 5.3.0 (OFL-1.1) for direction A
- tests: Vitest 5 with Testing Library and jsdom; new: `@playwright/test` 1.64.1 (Apache-2.0) and `@axe-core/playwright` 4.14.0 (MPL-2.0)
- AWS SAM CLI 1.170 and the AWS CLI for hosting; Gradle with the portable JDK 21 for the APK

**Spec:** `docs/superpowers/specs/2026-10-28-ms5-app-design.md`. It is binding, with the defaults of its §8 until Rene answers. Executors read both.

## Global Constraints

Lines marked *(plan)* are this plan's decisions; the rest restate the spec.

- **The screen line, exactly, on every screen, dialog and camera view, visible and on top without scrolling at 360 × 640:** `Lusot estimates depth at one spot. It is not advice to cross. Follow MMDA and local advisories.` It stays in English in both languages (C619).
- **Banned in every visible string, in both languages, in any case:** `safe` anywhere in a word (which covers safer, safest, safely, safety and unsafe) and `ligtas` anywhere in a word (kaligtasan, makaligtas), tested on visible text with `/safe|ligtas/i`, as MS4 does (amendment 6); at least the crossing phrases `you can cross`, `go ahead`, `pwedeng dumaan`, `tumawid ka`, `lusutan mo`, `you can pass`; and "MMDA's 9 levels" or "nine", "the 9 MMDA levels" in any form (C608). Each code review also reads new lines for crossing advice and whole-road wording. Levels and classes come only from the 9 levels and PATV, NPLV and NPATV, and no picture presents the 9 levels as MMDA's.
- **Names too** (amendment 3): no identifier, file name, string key, test title or commit message holds a banned form. The screen line's component is `ScreenLine`, its string key `layout.screenLine`, and the keys whose Taglish shows English until reviewed are screen-line keys (`isScreenLineKey`). MS1's CSS class `safe-area` and its `--safe-area-inset-*` variables, named after the platform's `env(safe-area-inset-*)`, stay. Third-party licence texts are never reworded: a hit in one goes to the controller (spec C608). Task 23 Step 1 checks the names with a grep.
- **Every level line says "at this spot"** (Taglish: "sa spot na ito"). No wording about a road or a route.
- **The 9 levels, in order:** `below_gutter`, `gutter`, `half_knee`, `half_tire`, `knee`, `tire`, `waist`, `chest`, `above_chest`; classes PATV for the first three, NPLV for `half_tire` and `knee`, NPATV for the rest (`backend/analysis/src/lusot_analysis/rules.py`). `below_gutter` and `above_chest` are outside MMDA's gauge.
- **The app never calls Meta.** It calls only the stack's API, the S3 upload link, OpenStreetMap's tiles, and the photo links the API returns.
- **Never shown, logged or kept beyond its screen:** a photo, a location, a report id (spec §4.4; the own pin's position and id may stay in memory until `GET /map/pins` shows it, at most 2 minutes). No report id shown as text on any screen, and no unpublished report's id in any route or log; a published pin's id appears only in its own route (C610, C620). No `console.log` of API bodies. Capacitor keeps `loggingBehavior: 'none'`.
- **Hash routes only:** `#/map`, `#/report`, `#/tested`, `#/about`, `#/privacy`, `#/pin/<id>` (C620), and `#/licences` *(plan, for C636)*. The app navigates to `#/pin/<id>` only from a pin it read from the API.
- **On-device storage** *(plan, for C607)*: `localStorage` keys `lusot.lang`, `lusot.theme`, `lusot.device`, `lusot.consent` (`{ adult: true, notice?: <version> }`), each read and written inside `try`/`catch`.
- **The gates (C605):** the 18+ check before the first sample, upload or question; the consent notice, with the same check, before the first upload or question, enforced on the screen itself, so a typed `#/report` meets it too.
- **Device id:** `crypto.randomUUID()`, sent as the `X-Lusot-Device` header on uploads, samples and flags (C606).
- **Polling (C601):** the next poll comes 2,000 ms after the last while under 60,000 ms since the upload finished, 5,000 ms while under 240,000 ms, and 15,000 ms after that; the last poll is at 600,000 ms. A 404, a network error, a request timeout or a 5xx keeps polling; a 429 waits for its `Retry-After` seconds when the browser can read them (N15; capped at the window's end), or else for the interval plus up to 1,000 ms of jitter. "Check again" polls the same report for another 600,000 ms from its own start, at the 15,000 ms interval, and never uploads.
- **Retries (C635):** `POST /uploads` and the S3 upload each retry once, about 2,000 ms later, on a network error, a request timeout, a 503 other than MS1's `uploads_paused`, or a throttling 429; a limit's 429 is never retried: `device_limit` or `global_cap` (MS4's C522), or Ask's `question_limit` or `question_cap` (amendment 4). The S3 retry reuses the same link within its 5 minutes. The photo stays in memory until it uploads or is 15 minutes old.
- **Camera (C602):** the in-app camera stream only, asking for about 1,920 × 1,080 from the rear camera. No timer runs while a permission prompt is open; once the stream opens, the first frame must arrive within 10,000 ms; a stream that resolves after its screen closed is stopped at once. A still under 1,600 px on its longer side shows a warning. No file input, no gallery, no camera plugin anywhere in the app.
- **Location (C603):** the watch starts only after the camera stream is open; the APK calls `Geolocation.requestPermissions()` first. The 20,000 ms window counts from the first position update. The fix must be 50 m or better; the pin moves at most 100 m from it, and `nudgeM` is `Math.min(100, Math.round(distance))`.
- **Photo:** longest side 1,600 px; JPEG quality 0.85, re-encoded at 0.75 when the first result is over 450 KB (C635).
- **Quality cutoffs** come from `quality.py`: brightness under 40.0 is `too_dark`, sharpness under 25.0 is `too_blurry`, dark checked first (C604).
- **Requests** *(plan, kept from MS1)*: one API call times out after 15,000 ms and the S3 upload after 60,000 ms, each rejecting with `RequestTimeoutError`.
- **Map:** tiles from `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, with the attribution `© OpenStreetMap contributors`, linked to `https://www.openstreetmap.org/copyright`, visible and on top, above the screen-line bar; the site never sends a `no-referrer` policy; the map's pins (`GET /map/pins`) refresh every 60,000 ms while the map is visible and when the app returns to the front; a live pin is full strength under 1 hour, faded from 1 hour, and gone at 3 hours; demo pins never fade and have no flag button; pin detail shows the flag count, never lower than the highest count already shown for that pin in the session (C612, C613; amendment 9). Under MS5-Q3 (a), approved, every published pin shows its photo and overlay while visible, from `GET /reports/{id}`; the rule goes by mode, so the person's own `live` result shows its photo for at most 3 hours, even unpublished (C614; amendment 6).
- **Overlay:** layers appear one after another over about 2,000 ms in all; with `prefers-reduced-motion: reduce`, the final frame shows at once (C615).
- **Design tokens:** text pairs at 4.5:1 or more and meaningful non-text pairs at 3:1 or more, in light and dark themes; touch targets of 48 px or more; depth on one hue, never traffic-light colours (C624, C625). Tokens follow MS5-Q1's default, direction A (Panukat).
- **Fonts and icons are bundled** (`@fontsource`, Lucide); no request to Google Fonts or any CDN (C623). The licences page carries the licence text of everything the web build and the APK ship (C636).
- **Copy review (C609, C619):** every line in both string tables carries a `reviewed` mark; lines Rene already fixed (the screen line, D19's refusal, C81's lines) start `true`, every new line `false`. Keys starting `refusal.`, `reason.`, `retake.`, `consent.` or `privacy.` are screen-line keys *(plan, the naming rule; Ask Lusot's branch adds `ask.answer.`)*: in Taglish they show their English text until their Taglish line is reviewed, and every English line on a Taglish screen carries `lang="en"`.
- **Credits:** Claude spends Meta credits only in Task 20 (about $1.35) and Task 21 (at most about $1.50). Both count toward the build's $60 automatic stop (MS4's C527; queue.md, "Spending limits"): log each run's billed cost in the ledger and send the tracker one line. If the stop trips, the tracker asks Rene, and nothing here raises it. Task 21's uploads are placed outside Metro Manila, so they are `private` and never pinned (C630). The testers' and Rene's own uploads are real reports, at about $0.032 each.
- **A pause** (C638; amendment 7): the paused line shows whatever set the model-calls switch: Rene, MS4's automatic spend stop ($60 during the build, $140 from the submission deploy) or the credits' lapse. The app can't tell them apart and doesn't try. A sample started during a pause gets MS4's saved result (Task 15 Step 6; amendment 10).
- **Hosting-agnostic** (amendment 8): until Rene answers MS5-Q4, the web app is a static build output (`app/dist`), served from a site's root. Hash routes need no rewrite rule, and no host's config file enters `app/`. The APK (`https://localhost`) and the local dev and preview servers are already in `AppOrigins`, so they reach the API meanwhile.
- **What never enters the repo:** photos (tests make their own images and video frames), plan text (cite "plan §N" and paraphrase), account IDs, console links, email addresses (the privacy contact comes from a git-ignored setting, C605), the Meta key, and names of user testers.
- **Sealed data:** nothing under a folder named `sealed` is opened, listed or searched. No Set A or A-neg photo is used.
- **Builds:** a Docker build and a Gradle build never run at the same time. Builds and deploys run in the foreground.
- **Deploys:** deploy only from a branch that holds everything already deployed, so merge `main` first: a stack deployed from a branch behind MS4 would roll MS4's code back. Under queue.md's rules for the shared `lusot` stack (Oct 30), no branch but MS4's deploys until MS4's integrated deploy (its Task 15) and its merge into `main`; and before any deploy, read the live template (`aws cloudformation get-template --stack-name lusot`, read-only), and stop and tell the tracker if the stack holds a resource this branch's template lacks. Announce `DEPLOY RUNNING` and `DEPLOY DONE` in this window's handoff note, as the other windows do.
- **Shells and commits:** start each PowerShell command with CLAUDE.md's PATH refresh. Commit from PowerShell after it, so the gitleaks hook runs. Conventional Commits, the message written to a file and passed with `git commit -F <file>`, ending with the attribution lines Claude Code gives the session. Never `--no-verify`.
- **Libraries:** check each new library's current API with Context7 before using it; pin it in the lockfile; credit it in the README in the task that adds it.
- **Tests** *(plan)*: app tests read other files through Vite's `?raw` imports and `import.meta.glob(..., { query: '?raw', import: 'default', eager: true })`, never `node:fs`, because `tsconfig.app.json` type-checks them without Node's types. Flags come from `import.meta.env.VITE_*`.

## Review Focus

Most likely first. Each line names the test that pins it.

1. **A double tap on "Send" or "Run this sample".** It must upload or run once, never twice, since each run is paid. Tests: Task 12 `send twice uploads once`, Task 15 `run twice starts one sample`.
2. **The first use, with two permission prompts.** A person reading the camera prompt must not hit a timeout; the location prompt must come after the camera's, since Android refuses two at once; and a stream that arrives after the screen closed must not leave the camera on. Tests: Task 9 `no timer while the camera prompt is open`, `a late stream is stopped`; Task 11 `the 20 s window starts at the first position`; Task 12 `the location watch starts after the camera opens`; Task 17's first-run emulator check.
3. **The map covers the screen line.** Leaflet's panes and controls sit at z-index 400 to 1,000, so a fixed bar over a full-height map can be hidden while still "in the viewport". Test: Task 18 `the screen line is on top`, using `document.elementFromPoint` at the line's centre on every route, every dialog, and every step of the report flow (the camera view and the place step's map included), and the same for the attribution.
4. **The person leaves the waiting screen, or the phone puts the app in the background, mid-analysis.** The poll keeps going or resumes at once, and the result is there when they come back. Tests: Task 12 `the wait survives a trip to the map`, `coming back to the app polls at once`.
5. **No camera, or no usable fix:** a laptop without a webcam, a refused prompt, a link opened in Messenger's or Facebook's in-app browser, or a fix that never reaches 50 m. The app says what to do, offers the samples, uploads nothing, and keeps the photo for a new try while it is under 15 minutes old. Tests: Task 9 `camera refused offers samples`, `in-app browser asks for a real browser`; Task 12 `poor fix keeps the photo for a retry`, `retry after 15 minutes asks for a new photo`.
