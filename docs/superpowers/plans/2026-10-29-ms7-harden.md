# MS7 Harden Implementation Plan

> **Draft: written before Rene approved the spec (D7).** It follows the spec's calls (C800 to C830) and the defaults of MS7-Q1 to MS7-Q8. If Rene changes a default, the tasks it names change with it, as each task says.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build MS7's checks as tested tools, rehearse the cloud checks once before the freeze, then run every check on the frozen stack on Nov 3 and close all 28 rows of plan Table 11.

**Architecture:**
- **The cloud checks** are locked PEP 723 scripts in `backend/scripts/`, beside `smoke_upload.py`. They share one helper module, `harden.py`, and the smoke script's helpers. Their logic is pure and tested on fakes: the schedules, the app's poll and retry rules, the verdicts, the policy decoder and the synthetic items. Only thin edges call AWS and the API.
- **The build and repo scans** add no dependency: `backend/scripts/scan_build.py` and `licences_py.py` in Python, and `scripts/licences.mjs` and `scripts/check_copy.mjs` in Node, with their rules in JSON files beside them.
- **The runs** (the rehearsal and the final run) are controller tasks. Their evidence goes into one results note, and PROGRESS points to it.

**Tech Stack:**
- Python 3.13 through uv 0.13.6: PEP 723 scripts locked with `uv lock --script`, using `boto3[crt]`, httpx 0.28, numpy and `opencv-python-headless` as `smoke_upload.py` pins them
- Node 22 with `node --test`
- gitleaks 8.30.1; pip-audit 2.10.1 through `uvx`; `aapt2` from Android build-tools 36
- MS5's Playwright 1.64.1
- the AWS CLI, always with `--profile lusot --no-cli-pager`

**Spec:** `docs/superpowers/specs/2026-10-29-ms7-harden-design.md`. It is binding, with the defaults of its §8 until Rene answers. Executors read both.

- **Private by construction (C803):**
  - Every upload sits at `OUTSIDE_POINT`, `{"lat": 14.35, "lng": 121.25}`: the middle of Laguna de Bay, outside Metro Manila and nobody's spot. Task 0 replaces it with MS5's live-check point if MS5 names one.

- **Two APIs** (MS4's C519, C521): the app's API serves every route but the public feed, `GET /map/pins` included, and the feed, `GET /pins.geojson`, has its own read-only API with its own stage. Scripts take both URLs from the stack's outputs with `api_urls` (Task 1).
  - The app's stage throttles at 10 a second with a burst of 20, except `GET /reports/{id}`, which has its own 30 and 60 (C508). The feed's stage throttles at 5 and 10 (C521).
  - The throttle probe uses two routes on the app stage's default, `GET /samples` and `GET /map/pins` (C806).
- **Never printed, logged or written:** the Meta key, the account ID, a report id, an upload form, a presigned URL, an S3 key or coordinates (C812).
  - Reports are named by ordinal with the script's letter in front: `L#1` (load test), `K#1` and `A#1` (upload checks), `S#1` (switch test).
  - Each run writes its own private file, `%LUSOT_DATA_DIR%\ms7\<YYYY-MM-DD>\ids-<script>-<HHMMSS>.json`, mapping ordinals to report ids and listing the run's device ids. No run overwrites another's.
  - Every printed line passes through `say()`, whose mask covers report ids and 12-digit runs, file names included.
- **Test fixtures build at run time** any 12-digit run, fake key, report id, email address, console or sign-in link, plan line, or `X-Amz-*` value (credential, token, signature). None appears as a literal in the repo, because the account-ID scan, gitleaks and the history scan read the repo (MS3a's `baa69a0`).
- **Clones without the plan** (MS8's N3): once MS3a's fail-closed plan-leak fix merges, `npm run check` exits 2 on any clone without the private plan, unless `CI=true`.
  - Every MS7 run is on this laptop, where the check reads the plan from its fixed staging path, so it passes in every worktree, the scan worktree of Task 22 included.
  - GitHub Actions sets `CI=true`, which skips only that step.
  - Judges never run `npm run check`: their path is MS6's one command, which reads no plan, and MS8's README outline explains what each check needs.
  - `check_history.mjs` follows the same rule, and fails without the plan in its export mode even in CI (Task 7a).
- **Server time:** every `capturedAt` a script sends is built from the server's clock, measured once per run from a response's `Date` header, since the laptop's ran 101 s fast on Oct 28.
- **Imported command-line modules** guard their command-line code with `if (import.meta.main)` in Node, as `scripts/deploy.mjs` does, and `if __name__ == "__main__"` in Python, so a test can import them without running them.
- **The app's rules, which the load test's phones follow** (C601, C635):
  - poll every 2 s below 60 s, every 5 s below 240 s and every 15 s below 600 s, then stop
  - a 429 waits for `Retry-After`, or else for the interval plus up to 1 s
  - `POST /uploads` and the S3 post each retry once, after 2 s, on a network error, a 503 or a throttling 429
  - a limit's 429 (`device_limit` or `global_cap`, MS4's C522) is never retried
- **Switches:** `/lusot/stop/uploads`, `/lusot/stop/publish` and `/lusot/stop/model-calls`. Only `off` lets work through. The API caches a switch for 30 s, and the feed is cached 60 s. Every set is undone in `finally`, and every run ends by reading all three as `off`.

- **AWS:**

  - read-only, except the switch sets, the synthetic items and their deletes
  - an error prints its code and HTTP status only

## Review Focus

Most likely first. Each line names the test that pins it.

1. **A crash halfway through the switch test, or a synthetic pin written too early.** Every switch is still `off` afterwards; the synthetic pin is written only after every API container has seen `publish` on, and never outlives it. Tests: Task 4 `test_switch_is_reset_when_the_check_raises`, `test_item_written_only_after_switch_cache`, `test_item_deleted_before_off_when_a_read_raises`, `test_failed_delete_keeps_publish_on`.
2. **A report id or an upload form escapes into printed output,** through an exception message or a debug line. Tests: Task 1 `test_scrub_masks_report_ids_and_account_ids`; Task 2 `test_run_prints_no_report_id_or_form`; Task 3 `test_checks_print_no_report_id`.
3. **The laptop's clock is wrong** (it was 101 s fast on Oct 28), so K3 posts before the link has expired, A2's old photo isn't old to the server, or every upload looks like it comes from the future. Tests: Task 1 `test_captured_at_uses_server_time`; Task 3 `test_hold_uses_server_time_under_skew`, `test_a2_uses_server_time_under_skew`.
4. **The index lags,** so the precondition's first read of a new report is a 404. The run must wait for it, and must still send no photo until `private` is confirmed. Tests: Task 1 `test_confirm_private_waits_through_404`, `test_confirm_private_refuses_live`.
5. **A secret hides in a binary or non-UTF-8 file,** such as `classes.dex` or a UTF-16 resource. The scan finds it and prints only the file name. Tests: Task 6 `test_exact_bytes_found_in_a_binary_member`, `test_utf16_secret_is_found`, `test_output_never_holds_the_secret`; Task 7 `scans UTF-16 text`.

  - `new_device_id() -> str`: `str(uuid.uuid4())`
  - `data_dir() -> Path`: `LUSOT_DATA_DIR`, or else `C:\Systems\Lusot\lusot-data`. It raises `CheckFailed` for a path with a part named `sealed`.

  - `wait_after_429(retry_after: str | None, interval_s: float, rng: random.Random) -> float`

  - `ipv4_client(timeout_s: float = 30.0) -> httpx.Client`
  - `upload_body(point: dict, *, captured_at: datetime) -> dict`: the body MS5's app sends to `POST /uploads`, with Task 0's field names: `lat`, `lng`, `gpsAccuracyM` 10, `capturedAt` (UTC, milliseconds), `nudgeM` 0 and the current `consentVersion`

  - `geohash6(lat: float, lng: float) -> str`
